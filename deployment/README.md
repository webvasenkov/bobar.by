# BOBAR на VPS

Подготовлено для bobar.by, Docker Compose и Caddy. Node.js 24 + Next.js standalone;
дизайн и компоненты общие с версией Sites. Только серверный runtime заменяется
при сборке. SQLite находится в постоянном Docker volume, не в Git.

## До запуска

1. Проверить существующие сайты: `docker ps`, `ss -lntup`, `systemctl status caddy`.
   Этот Compose занимает 80/443. Если они заняты, не останавливать существующий
   proxy: добавить BOBAR в его конфигурацию и использовать отдельный upstream.
2. В действующей DNS-зоне выставить A-запись `@` на `103.167.18.80`.
   Не менять MX/TXT и NS. Проверить существующую AAAA: она должна вести на этот
   сервер; неверную AAAA исправить до выпуска сертификата.
3. Открыть входящие TCP 80/443. UDP 443 нужен только для HTTP/3.
4. На сервере нужны Docker Engine, Compose v2 и Git. Проверить `docker compose version`.

## Установка (после загрузки исходников в GitHub)

```sh
git clone https://github.com/webvasenkov/bobar.by.git /opt/bobar
cd /opt/bobar
cp deployment/env.example .env
chmod 600 .env
# При необходимости заполнить Telegram-переменные в .env на сервере.
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs --tail=100 caddy
curl -I https://bobar.by
```

Никаких паролей сервера/хостинга в `.env` не требуется. Telegram не настроен
автоматически: без токена и chat ID заявки сохраняются, уведомления не отправляются.
Форма принимает Origin https://bobar.by. Caddy перезаписывает служебный заголовок
IP, приложение не публикует порт 3000 в интернет.

Caddy автоматически получает и продлевает HTTPS-сертификат и перенаправляет HTTP
на HTTPS. Данные сертификатов сохраняются в `caddy_data`. Если DNS ещё не указывает
на сервер или порты закрыты, выпуск сертификата не завершится.

## Обновление и откат

### Управление работами

После установки этой версии откройте `https://bobar.by/admin`. Создайте доступ
на сервере один раз:

```sh
cd /opt/bobar
python3 deployment/setup-admin.py
docker compose up -d --build
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
```

Скрипт выводит логин и случайный пароль. Сохраните их в менеджере паролей.
В `.env` попадают только логин и PBKDF2-хеш с индивидуальной солью. Telegram-настройки
сохраняются. Для смены забытого пароля: `python3 deployment/setup-admin.py --reset`,
затем `docker compose up -d --no-deps --force-recreate app`. Старые сессии станут
недействительными. Обычная сессия действует 12 часов.

В админке доступны название, описание, ссылка, отдельные скриншоты компьютера и
телефона, порядок и скрытие. Новые работы сначала скрыты. Для публикации нужны оба
скриншота. Три существующие работы импортируются один раз без изменения изображений;
перед сохранением их опубликованных правок нужно добавить мобильные версии.
Скрытую работу можно сохранить с незаполненными скриншотами.

PNG, JPEG и WebP принимаются до 8 МиБ и 40 мегапикселей. Изображения проверяются
по содержимому. В публичном слайдере на ширине до 767 px используется мобильный
скриншот; в остальных случаях – компьютерный. Публикация работает без пересборки.
Работы хранятся в SQLite, загруженные изображения – в постоянном volume `uploads`.
Неиспользуемые загрузки сохраняются, поэтому замена изображения не удаляет файл.

Для Sites используются D1 и R2 с теми же API. Это отдельная база и отдельные файлы:
изменения в приватном предпросмотре не синхронизируются с VPS автоматически.
На действующем VPS обновление применяет миграцию схемы 1 → 2, сохраняя заявки.
После неё не запускайте старый сервер со схемой 1 на обновлённой базе; для отката
понадобится резервная копия до обновления.

### Подключение Telegram

Создать бота через @BotFather и отправить ему `/start` с аккаунта получателя.
Нужны токен бота и числовой chat ID получателя. Не использовать токен другого
проекта без необходимости. Токен вводится только на сервере, не в исходниках.

```sh
cd /opt/bobar
python3 deployment/setup-telegram.py
docker compose up -d --no-deps --force-recreate app
```

Скрипт проверяет бота и чат через Telegram API, показывает получателя и после
подтверждения отправляет тест. Затем атомарно обновляет только Telegram-параметры
в `.env` с правами `600`. Остальные параметры сохраняются. Если проверка не прошла,
настройки не меняются. Перезапуск приложения нужен для применения переменных.

После этого отправить одну проверочную заявку через сайт и проверить сообщение.
Если Telegram недоступен, заявка остаётся в SQLite; автоматической повторной
доставки уведомлений пока нет. Токен не попадает в клиентский код.

Описание API: https://core.telegram.org/bots/api#sendmessage

### Обновление исходников

Перед обновлением записать текущий commit и сделать резервную копию SQLite и загрузок.
Не выполнять `docker compose down -v`: это удалит заявки, портфолио, скриншоты и сертификаты.

```sh
git rev-parse HEAD
git pull --ff-only
docker compose up -d --build
docker compose exec caddy caddy reload --config /etc/caddy/Caddyfile
```

Для отката переключить исходники на записанный commit и повторить сборку.
Будущие изменения схемы БД требуют отдельного плана отката данных.

## Резервная копия

Создать согласованную копию внутри volume (имя не должно существовать):

```sh
docker compose exec app node -e 'const {DatabaseSync}=require("node:sqlite");const db=new DatabaseSync(process.env.DATABASE_PATH);db.exec("VACUUM INTO '\''/app/data/backup.sqlite'\''");db.close()'
mkdir -p backups
docker compose cp app:/app/data/backup.sqlite ./backups/backup.sqlite
docker compose cp app:/app/uploads ./backups/uploads
```

На время копирования не редактировать работы в админке. Хранить базу и папку загрузок
вместе вне сервера. Не копировать только основной файл живой WAL-базы.
Ранее сохранённые заявки Cloudflare D1 автоматически не переносятся.

## Проверки подготовки

`npm run build:vps` собирает отдельный серверный артефакт.
`node tests/vps-smoke.mjs` проверяет standalone-сборку без Telegram и реальных заявок.
`node tests/admin-smoke.mjs` проверяет вход, ограничение попыток, загрузку и приватность
изображений, публикацию, порядок, конфликты правок, миграцию старой базы и перезапуск.
Обычный `npm run build` по-прежнему предназначен для Sites/Cloudflare.

Docker, DNS и сертификат необходимо проверить непосредственно на VPS: из текущей
среды SSH недоступен. Сервер и DNS здесь не изменялись.

Документация:
- https://nextjs.org/docs/app/api-reference/config/next-config-js/output
- https://nodejs.org/api/sqlite.html
- https://caddyserver.com/docs/automatic-https
